CLUSTER ADMIN 14 LABS

Lý thuyết tuần 9 — kubeadm workflow
01kubeadm init phases: preflight → certs → kubeconfig → kubelet-start → control-plane → etcd → upload-config → upload-certs → mark-control-plane → bootstrap-token → addons. Mỗi phase có thể chạy riêng.
02kubeadm join: Worker node dùng bootstrap token để join. Token expire sau 24h mặc định. Tạo token mới: kubeadm token create --print-join-command.
03CNI (Container Network Interface): Phải cài sau kubeadm init. Phổ biến: Flannel (simple), Calico (NetworkPolicy support), Weave. Nodes NotReady cho đến khi cài CNI.
04Certificate rotation: kubeadm certs check-expiration. kubeadm certs renew all. Các cert trong /etc/kubernetes/pki/ expire sau 1 năm mặc định.
05kubelet configuration: /etc/kubernetes/kubelet.conf (kubeconfig cho kubelet), /var/lib/kubelet/config.yaml (kubelet config). Restart: systemctl restart kubelet sau khi thay đổi.

Cluster Upgrade & etcd Backup/Restore
// kubeadm upgrade · drain · etcdctl snapshot · restore procedure
CRITICAL EXAM 16 LABS
▾
Lý thuyết tuần 10 — phải thuộc lòng
01Upgrade order: Luôn upgrade control-plane TRƯỚC worker nodes. Không được skip minor version (1.28 → 1.29 → 1.30, không nhảy 1.28 → 1.30). Upgrade từng node một.
02Upgrade procedure per node: (1) drain node, (2) apt install kubeadm=new-version, (3) kubeadm upgrade apply/node, (4) apt install kubelet=kubectl=new-version, (5) restart kubelet, (6) uncordon node.
03etcd backup: Dùng etcdctl với TLS certs. Phải specify đúng endpoints, cacert, cert, key. Snapshot file là binary, không đọc được trực tiếp.
04etcd restore procedure: (1) snapshot restore → new data-dir, (2) edit etcd static pod manifest: --data-dir=new-path, (3) etcd pod tự restart, (4) verify cluster healthy.
# ═══ CLUSTER UPGRADE — CONTROL PLANE ═══ # 1. Drain control-plane kubectl drain controlplane --ignore-daemonsets --delete-emptydir-data # 2. Install new kubeadm apt-mark unhold kubeadm apt install -y kubeadm=1.29.0-00 apt-mark hold kubeadm # 3. Verify and apply kubeadm upgrade plan kubeadm upgrade apply v1.29.0 # 4. Install new kubelet + kubectl apt-mark unhold kubelet kubectl apt install -y kubelet=1.29.0-00 kubectl=1.29.0-00 apt-mark hold kubelet kubectl systemctl daemon-reload && systemctl restart kubelet # 5. Uncordon kubectl uncordon controlplane # ═══ ETCD BACKUP ═══ ETCDCTL_API=3 etcdctl snapshot save /opt/backup/etcd-$(date +%F).db \ --endpoints=https://127.0.0.1:2379 \ --cacert=/etc/kubernetes/pki/etcd/ca.crt \ --cert=/etc/kubernetes/pki/etcd/server.crt \ --key=/etc/kubernetes/pki/etcd/server.key # ═══ ETCD RESTORE ═══ ETCDCTL_API=3 etcdctl snapshot restore /opt/backup/etcd-2024-01-01.db \ --data-dir=/var/lib/etcd-restore # Edit static pod manifest vi /etc/kubernetes/manifests/etcd.yaml # Change: --data-dir=/var/lib/etcd → --data-dir=/var/lib/etcd-restore # Also update hostPath volume to match new data-dir
⚠ HAY RA THI: Sau restore, phải sửa CẢ HAI chỗ trong etcd.yaml: --data-dir flag VÀ volumes.hostPath.path. Nếu chỉ sửa 1 → etcd không start!
16 Labs — Upgrade & Backup
L01–L05
Full Cluster Upgrade 1.28 → 1.29
Upgrade toàn bộ cluster, từng node một theo đúng quy trình.
  • Tạo deployment 3 replicas, verify sau upgrade vẫn chạy
  • Upgrade control-plane: drain → kubeadm upgrade apply → kubelet restart → uncordon
  • Upgrade worker1: drain → kubeadm upgrade node → kubelet restart → uncordon
  • Upgrade worker2: tương tự
  • k get nodes -o wide → tất cả VERSION=v1.29.0
All nodes: Ready, VERSION=v1.29.0. Deployment vẫn running với 3 replicas.
L06–L09
etcd Backup & Restore — Full Cycle
Backup → tạo thêm resources → restore → verify rollback.
  • Tạo 5 deployments: web1, web2, web3, db1, cache1
  • Backup etcd: etcdctl snapshot save /opt/backup/before.db ...
  • Xóa web3, web4 deployments (simulate disaster)
  • Tạo thêm deployment "new-app" (sau backup)
  • Restore: etcdctl snapshot restore /opt/backup/before.db --data-dir=/var/lib/etcd-restore
  • Edit /etc/kubernetes/manifests/etcd.yaml → data-dir mới
  • Chờ etcd restart → k get deploy → web1-5 có, new-app không có
State khôi phục về đúng thời điểm backup. new-app (tạo sau backup) biến mất.
L10–L12
etcd Snapshot Verification
Verify integrity của backup file.
  • ETCDCTL_API=3 etcdctl snapshot status /opt/backup/before.db --write-out=table
  • Xem: Hash, Revision, Total Keys, Total Size
  • Tạo corrupt backup (truncate file), verify → error message rõ ràng
L13–L16
etcd trên external node (Multi-node etcd)
Backup khi etcd ở node khác (common CKA scenario).
  • k get pods -n kube-system etcd-* -o yaml | grep -- --listen-client-urls
  • Xác định etcd endpoint từ static pod manifest
  • SSH vào etcd node, thực hiện backup với đúng certs
  • Copy snapshot về control-plane node cho restore
Backup từ node khác vẫn restore được trên control-plane node

// node failures · control plane components · kubelet · scheduler · controller
30% EXAM 18 SCENARIOS
▾
Debug methodology — Luôn theo thứ tự này
①Xác định scope: Vấn đề ở cluster level (node) hay app level (pod)? kubectl get nodes → kubectl get pods -A
②Node issues: kubectl describe node → Conditions. SSH vào node → systemctl status kubelet → journalctl -u kubelet --since "5m ago"
③Control plane issues: kubectl get pods -n kube-system → kubectl logs POD -n kube-system. Static pods: ls /etc/kubernetes/manifests/
④App issues: kubectl describe pod → Events section là vàng. kubectl logs pod → kubectl logs pod --previous. kubectl get events --sort-by=.lastTimestamp
18 Troubleshooting Scenarios
SCN 01 Node NotReady — kubelet crashed
injectsystemctl stop kubelet trên worker1
symptomk get nodes → worker1: NotReady. Pods trên đó: Unknown
debugk describe node worker1 → Conditions: Ready False. SSH worker1: systemctl status kubelet → inactive (dead)
fixsystemctl start kubelet → systemctl enable kubelet
Verify: k get nodes → worker1 Ready trong ~60s
SCN 02 Node NotReady — network plugin down
injectk delete ds calico-node -n kube-system (hoặc tên CNI plugin DS)
symptomk get nodes → NotReady sau vài phút. Pods không communicate được
debugk describe node → NetworkPluginNotReady. k get pods -n kube-system → CNI pods missing
fixReinstall CNI: kubectl apply -f calico.yaml
SCN 03 kube-scheduler down — Pods Pending
injectmv /etc/kubernetes/manifests/kube-scheduler.yaml /tmp/ (disable static pod)
symptomDeploy mới tạo → pods Pending mãi không schedule
debugk get pods -n kube-system → kube-scheduler pod missing. k describe pod pending-pod → "0/2 nodes are available: 2 node(s) had scheduling errors"
fixmv /tmp/kube-scheduler.yaml /etc/kubernetes/manifests/ → scheduler restores
Verify: Pending pods tự schedule sau vài giây
SCN 04 kube-apiserver down — kubectl not responding
injectEdit /etc/kubernetes/manifests/kube-apiserver.yaml: add typo vào --etcd-servers flag
symptomkubectl get → "The connection to the server was refused"
debugSSH control-plane. crictl pods | grep apiserver. crictl logs APISERVER_POD_ID
fixEdit /etc/kubernetes/manifests/kube-apiserver.yaml → fix typo → chờ pod restart
⚠ Phải dùng crictl (không dùng được kubectl khi apiserver down)
SCN 05 etcd unhealthy
injectEdit etcd manifest: --initial-cluster-token typo
symptomkubectl get → slow/error. k get cs → etcd Unhealthy
debugcrictl logs ETCD_CONTAINER. Xem error messages
fixSửa lại manifest đúng → etcd restart
SCN 06–10 Node disk pressure, memory pressure, PID pressure
injectdd if=/dev/zero of=/bigfile bs=1M count=10000 (fill disk)
symptomk describe node → Conditions: DiskPressure=True. Pods bị evict
debugdf -h trên node. journalctl -u kubelet | grep evict
fixrm /bigfile → kubelet tự recover sau vài phút

SCN 04ImagePullBackOff — private registry

DRILL 03
RBAC full setup — Mục tiêu: 5 phút
SA + Role (get/list pods,services) + RoleBinding + verify can-i
  • k create sa app-sa -n dev
  • k create role app-role --verb=get,list --resource=pods,services -n dev
  • k create rolebinding app-rb --role=app-role --serviceaccount=dev:app-sa -n dev
  • k auth can-i list pods --as=system:serviceaccount:dev:app-sa -n dev
DRILL 04
PV + PVC + Pod mount — Mục tiêu: 5 phút
  • Tạo PV (hostPath 1Gi RWO Retain) từ YAML
  • Tạo PVC (500Mi RWO) → verify Bound
  • Deploy pod mount PVC → /data
  • exec: echo "test" > /data/f.txt
DRILL 05
etcd backup + verify — Mục tiêu: 3 phút

  • etcdctl snapshot save /opt/snap.db --endpoints... --cacert... --cert... --key...

Snapshot status shows: hash, revision, keys — trong <3 phút
