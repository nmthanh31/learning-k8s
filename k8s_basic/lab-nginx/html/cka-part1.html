// control plane · worker node · pod lifecycle · multi-container patterns
THEORY 18 LABS
▾
Lý thuyết tuần 1 — phải thuộc trước khi thực hành
01Control Plane components: kube-apiserver (cổng vào duy nhất, RESTful, xác thực/uỷ quyền), etcd (key-value store, source of truth), kube-scheduler (chọn node cho pod dựa trên resource/taint/affinity), kube-controller-manager (chạy nhiều controller: replication, node, endpoints...)
02Worker Node components: kubelet (agent trên mỗi node, nhận PodSpec từ apiserver, tạo/monitor container), kube-proxy (quản lý iptables/ipvs rules cho Service networking), container runtime (containerd/CRI-O)
03Pod là đơn vị nhỏ nhất trong K8s. Một Pod = 1 hoặc nhiều container chia sẻ network namespace (cùng IP, cùng port space) và có thể chia sẻ storage volumes.
04Pod lifecycle: Pending → Running → Succeeded/Failed. Container states: Waiting, Running, Terminated. Pod conditions: PodScheduled, ContainersReady, Initialized, Ready.
05Multi-container patterns: Sidecar (log shipper, proxy), Ambassador (proxy external services), Adapter (transform output). InitContainers chạy tuần tự trước main containers, phải exit 0 mới tiếp tục.
06Namespace: Phân vùng logical trong cluster. Default namespaces: default, kube-system, kube-public, kube-node-lease. DNS pattern: service-name.namespace.svc.cluster.local

W02
Deployments, ReplicaSets & Workloads
// rolling update · rollback · DaemonSet · StatefulSet · Job · CronJob
WORKLOADS 20 LABS
▾
Lý thuyết tuần 2
01Deployment quản lý ReplicaSet, đảm bảo desired state. Hỗ trợ rolling update (maxSurge, maxUnavailable) và rollback qua revision history.
02ReplicaSet đảm bảo số lượng pod replicas. Selector label phải match pod template labels. Deployment tạo RS mới khi update image.
03DaemonSet đảm bảo mỗi node chạy đúng 1 pod. Dùng cho: log collectors (fluentd), monitoring agents (node-exporter), CNI plugins. Khi add node mới, DS tự tạo pod.
04StatefulSet cho stateful apps (databases). Pod có stable hostname (pod-0, pod-1...), persistent storage riêng từng pod, ordered deployment/scaling.
05Job chạy pod cho đến khi hoàn thành (exit 0). completions, parallelism, backoffLimit. CronJob tạo Job theo schedule (cron format). concurrencyPolicy: Allow/Forbid/Replace.

W03
ConfigMap, Secret & Resource Management
// env injection · volume mount · requests/limits · LimitRange · ResourceQuota
CONFIG 18 LABS
▾
Lý thuyết tuần 3
01ConfigMap lưu non-sensitive config data. 4 cách tạo: literal, from-file, from-env-file, YAML. 3 cách dùng: envFrom, env[].valueFrom, volume mount.
02Secret lưu sensitive data (base64 encoded, NOT encrypted by default). Types: Opaque, kubernetes.io/tls, kubernetes.io/dockerconfigjson. Inject giống ConfigMap.
03Resource Requests là lượng tài nguyên scheduler dùng để chọn node. Limits là mức tối đa container được dùng. CPU throttle khi vượt limit. Memory OOMKill khi vượt limit.
04LimitRange set default/min/max cho containers trong namespace. ResourceQuota giới hạn tổng tài nguyên trong namespace (pods, CPU, memory, PVC...).
05Quality of Service classes: BestEffort (no requests/limits), Burstable (requests ≠ limits), Guaranteed (requests = limits). Thứ tự bị evict: BestEffort → Burstable → Guaranteed.

W04
Scheduling Chuyên Sâu
// nodeSelector · affinity · taints · tolerations · static pods · priority
SCHEDULING 20 LABS
▾
Lý thuyết tuần 4 — Scheduling pipeline
01Scheduler pipeline: Filter (loại node không đủ điều kiện) → Score (rank node còn lại) → Bind (gán pod vào node cao điểm nhất)
02nodeSelector — đơn giản nhất. Label node → set nodeSelector trong pod spec. nodeAffinity — mạnh hơn: requiredDuring (hard) vs preferredDuring (soft). Hỗ trợ operators: In, NotIn, Exists, DoesNotExist, Gt, Lt.
03podAffinity/podAntiAffinity — schedule pod gần/tránh xa pod khác. Dùng topologyKey (thường là kubernetes.io/hostname). Use case: co-locate app+cache, tách replica ra nhiều node.
04Taints & Tolerations: Taint trên node ngăn pod không có toleration lên. 3 effects: NoSchedule (cứng), PreferNoSchedule (mềm), NoExecute (evict cả pod đang chạy). Toleration trong pod để bypass taint.
05Static Pods: Manifest đặt trong /etc/kubernetes/manifests/ → kubelet tự tạo, không qua API server. Control plane components (apiserver, etcd, scheduler, controller-manager) đều là static pods.
06Manual scheduling: Set spec.nodeName trong pod YAML. Scheduler bị bypass hoàn toàn. Nếu node không tồn tại, pod Pending mãi.

W05
Services & DNS Mastery
// ClusterIP · NodePort · LoadBalancer · ExternalName · Headless · CoreDNS
NETWORKING 22 LABS
▾
Lý thuyết tuần 5
01Service types: ClusterIP (virtual IP internal, default), NodePort (expose port 30000-32767 trên tất cả nodes), LoadBalancer (cloud LB), ExternalName (CNAME alias).
02Endpoint: Khi tạo Service, Endpoint object được tạo tự động chứa IP:Port của pods matching selector. Nếu selector không match → Endpoints rỗng → service không route được.
03CoreDNS: DNS server trong kube-system. Mỗi Service có DNS record: [service].[namespace].svc.cluster.local. Pod có DNS: [pod-ip-dashes].[namespace].pod.cluster.local
04kube-proxy: Chạy trên mỗi node, sync iptables/IPVS rules từ Service/Endpoint objects. Actual packet routing do kernel handle, không đi qua kube-proxy process.
05Headless Service (clusterIP: None): Không có virtual IP. DNS trả về IP trực tiếp của pods. Dùng với StatefulSet để access từng pod riêng lẻ.

Storage: PV, PVC & StorageClass
// persistent volumes · claims · access modes · reclaim policy · dynamic provisioning
STORAGE 16 LABS
▾
Lý thuyết tuần 7
01Volume vs PersistentVolume: Volume gắn vào Pod, mất khi Pod xóa. PersistentVolume (PV) tồn tại độc lập, tạo bởi admin. PersistentVolumeClaim (PVC) là "yêu cầu" storage của user.
02Binding: PVC bind với PV theo capacity (PVC ≤ PV), access modes (phải match), storageClassName (phải match hoặc cả 2 empty). Sau bind: 1-to-1 (1 PV chỉ bind 1 PVC).
03Access Modes: ReadWriteOnce (RWO) — 1 node read+write, ReadOnlyMany (ROX) — nhiều node read-only, ReadWriteMany (RWX) — nhiều node read+write. Phụ thuộc storage backend hỗ trợ gì.
04Reclaim Policy: Retain (PV không bị xóa, status Released, data còn), Delete (PV + underlying storage bị xóa), Recycle (deprecated, xóa data rồi Available lại).
05StorageClass: Cho phép dynamic provisioning. Admin tạo StorageClass với provisioner. User tạo PVC reference StorageClass → PV tự động tạo. Mặc định StorageClass có annotation storageclass.kubernetes.io/is-default-class.
16 Labs — Storage
L01–L04
PV/PVC Static Provisioning
Tạo PV hostPath, PVC bind, mount vào pod.
  • Tạo PV: hostPath /data/pv1, capacity 1Gi, RWO, Retain
  • Tạo PVC: 500Mi, RWO → bind với PV
  • k get pv,pvc → STATUS: Bound
  • Deploy pod mount PVC → /data
  • Exec pod: echo "test" > /data/file.txt
  • Delete pod, recreate pod, exec: cat /data/file.txt → vẫn còn!
Data persists qua pod restart. PV STATUS = Bound khi có PVC.
L05–L08
Reclaim Policy — Retain vs Delete
Quan sát PV lifecycle khi PVC bị xóa.
  • PV1 với Retain: xóa PVC → PV status = Released (không Available lại)
  • PV2 với Delete: xóa PVC → PV bị xóa luôn
  • Để reuse Retained PV: xóa claimRef trong PV spec (k edit pv)
Released PV không bind với PVC mới cho đến khi xóa claimRef.
L09–L12
Volume Types — emptyDir, hostPath, configMap, secret
Thực hành từng loại volume.
  • emptyDir: 2 containers share temp storage, container1 write, container2 read
  • hostPath: mount /var/log từ host vào pod để đọc node logs
  • configMap as volume: nginx.conf từ ConfigMap mount vào /etc/nginx/
  • secret as volume: TLS cert/key mount vào /etc/ssl/
L13–L16
StorageClass & Dynamic Provisioning
Cài local-path provisioner, test dynamic PV creation.
  • Cài rancher local-path-provisioner (hoạt động tốt với kind)
  • Set làm default StorageClass
  • Tạo PVC không specify storageClassName → dynamic PV tạo tự động
  • k get pv → thấy PV mới với suffix random
PVC → Bound trong vài giây. PV tự tạo match đúng size.

Security — RBAC, ServiceAccount, SecurityContext
// role · clusterrole · bindings · serviceaccount · pod security · TLS
SECURITY 20 LABS
▾
Lý thuyết tuần 8
01RBAC flow: Subject (User/Group/ServiceAccount) → RoleBinding/ClusterRoleBinding → Role/ClusterRole → Resources + Verbs. Role là namespace-scoped, ClusterRole là cluster-wide.
02Verbs: get, list, watch, create, update, patch, delete, deletecollection. Aggregated verbs: * = tất cả.
03ServiceAccount: Identity của pod khi giao tiếp với API server. Default SA trong mỗi namespace. Token tự mount vào /var/run/secrets/kubernetes.io/serviceaccount/
04SecurityContext: Pod-level và container-level. runAsUser/runAsGroup (UID/GID), fsGroup (volume ownership), runAsNonRoot, readOnlyRootFilesystem, allowPrivilegeEscalation, capabilities.
05kubectl auth can-i: Check permission của user/SA. --as flag để impersonate. --as-group để test group permissions.
20 Labs — Security
L01–L05
RBAC — Role & RoleBinding
Tạo Role với permissions cụ thể, bind cho SA.
  • k create sa dev-reader -n dev
  • k create role pod-reader --verb=get,list,watch --resource=pods -n dev
  • k create rolebinding dev-rb --role=pod-reader --serviceaccount=dev:dev-reader -n dev
  • k auth can-i list pods --as=system:serviceaccount:dev:dev-reader -n dev → yes
  • k auth can-i delete pods --as=system:serviceaccount:dev:dev-reader -n dev → no
can-i trả về đúng theo permissions đã set.
L06–L09
ClusterRole & ClusterRoleBinding
Cluster-wide permissions cho SA.
  • k create clusterrole node-reader --verb=get,list,watch --resource=nodes
  • k create clusterrolebinding node-rb --clusterrole=node-reader --serviceaccount=default:default
  • Tạo pod dùng default SA, exec vào, curl API server với token
  • curl https://kubernetes/api/v1/nodes -H "Authorization: Bearer $TOKEN" --cacert /run/secrets/.../ca.crt
API call trả về node list. Non-permitted endpoints trả về 403.
L10–L13
ServiceAccount — Custom SA cho Pod
Tạo SA với min permissions, gắn vào pod.
  • Tạo SA backend-sa với Role: get/list/watch pods,services
  • Tạo pod với serviceAccountName: backend-sa
  • automountServiceAccountToken: false cho pods không cần API access
  • Exec pod: ls /run/secrets/kubernetes.io/serviceaccount/
L14–L17
SecurityContext — Pod & Container Level
Harden pods với security constraints.
  • Pod securityContext: runAsUser=1000, fsGroup=2000
  • Exec pod: id → uid=1000. ls -la /data → group=2000
  • Container: readOnlyRootFilesystem=true → touch /tmp/test → permission denied
  • Container: allowPrivilegeEscalation=false, drop capability NET_RAW
Processes run as non-root. Write to rootfs fails.
L18–L20
Certificate & kubeconfig
Tạo user certificate, cấu hình kubeconfig.
  • openssl genrsa -out dev.key 2048
  • openssl req -new -key dev.key -out dev.csr -subj "/CN=dev-user/O=developers"
  • Tạo CertificateSigningRequest object trong K8s, approve
  • k config set-credentials dev-user --client-certificate=dev.crt --client-key=dev.key
  • k config set-context dev-context --cluster=... --user=dev-user --namespace=dev
k --context=dev-context get pods → hoạt động với permissions của dev-user
